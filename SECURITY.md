# Security and privacy

Report vulnerabilities privately through GitHub private vulnerability reporting if enabled; otherwise contact the maintainer privately. Never attach actual payroll, invoices, bank files, personal identifiers or credentials to public issues. Use synthetic reproductions.

Local CLI makes no network calls but does not encrypt files or control access. Use organization-approved storage, least privilege, encrypted devices/backups, pseudonymous references, data minimization, retention/deletion policy and approved execution environments. Do not upload real data to agent hosts by default. Review Git diffs before publishing; .gitignore does not guarantee prevention of disclosure. If secrets are exposed, rotate them and follow incident response procedures; making a repository private is not sufficient.

Outputs may be sensitive. Do not run untrusted code or files with elevated privileges. No payment execution or automatic adverse decisions. Human reviewer is responsible for interpretation.

Report files are created with the default permissions of the account that runs the tool; store them in access-restricted folders. While a report is being written a temporary file named `.brfc-<random>.tmp` exists briefly in the output folder and is removed afterwards; do not place the output in a synchronized folder you do not control. Markdown reports escape HTML, link syntax and table separators in free text supplied by the user (such as the policy `source`). Bare URLs, e-mail addresses, emphasis markers and Unicode control characters in that text are **not yet neutralized** (a fix is in progress); treat shared reports as sensitive and review the policy `source` before sharing a Markdown report. The toolkit exposes no network service and no MCP tools; any future financial MCP tool must require authentication and authorization before it is shipped.

**Português:** relate vulnerabilidades de forma privada; nunca anexe folha, notas fiscais, extratos, identificadores pessoais ou credenciais reais a issues públicas — use reproduções sintéticas. O programa local não faz chamadas de rede, não criptografa arquivos nem controla acesso: use armazenamento aprovado pela organização, mínimo privilégio e dispositivos criptografados. Relatórios podem ser sensíveis e são criados com as permissões padrão da conta; guarde-os em pastas com acesso restrito. Durante a gravação existe brevemente um arquivo temporário `.brfc-<aleatório>.tmp` na pasta de saída. Relatórios em Markdown escapam HTML, sintaxe de links e separadores de tabela no texto livre informado pelo usuário (como a `source` da política); URLs soltas, e-mails, marcadores de ênfase e caracteres de controle Unicode nesse texto **ainda não são neutralizados** (correção em andamento): revise a `source` antes de compartilhar um relatório em Markdown. Não há serviço de rede nem ferramentas MCP; qualquer ferramenta MCP financeira futura exigirá autenticação e autorização. Nenhum pagamento é executado e nenhuma decisão adversa é automática: a interpretação é do revisor humano.
